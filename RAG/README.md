## チャンクの作り方

- 1チャンク＝1つの話題。`##` の見出しから始め、見出しと本文に町丁目名や話題を必ず書く（検索で単独で取り出されても意味が通るように）。
- チャンクの中に空行を入れない。チャンクの間は空行1つで区切る。
- 1チャンクはおおむね500文字以内（2026-09-25時点の最長は `01_地域の背景.md` の出典の一覧で563文字、町丁目ファイルは409文字）。

## Difyでの設定（チェックリスト）

ナレッジ名は `naisui-knowledge`。2026-09-28に、経済的インデックス・1行ごとのチャンクで作られていて「土のうはどこ？」に答えられなかったため、この設定に直した。

### A. ナレッジベースの設定（1回だけ）

「ナレッジ」→ `naisui-knowledge` →「設定」。

- [ ] インデックス方法: **高品質**（経済的には戻せないが、戻す必要はない）
- [ ] 埋め込みモデル: **gemini-embedding-001**（欄に名前が出て、「非互換」の表示が消えていること）
- [ ] 検索設定: **ハイブリッド検索** →「**ウェイト設定**」（Rerankモデルは使わない）
- [ ] ウェイト: セマンティック **0.5** ／ キーワード **0.5**（町丁目名・「土のう」・通り名などの言葉の一致を効かせる。0.7／0.3でも動く）
- [ ] トップK: **5**
- [ ] スコア閾値: **オフ**
- [ ] 「保存」

### B. ドキュメントごとのチャンク設定（13ファイルそれぞれ）

ドキュメントの一覧でファイルを開き、「チャンク設定」を変えて「保存して処理」。13ファイルとも同じ設定にする。

| 項目 | 設定 |
| --- | --- |
| チャンク構造 | General（汎用） |
| チャンク識別子 | `\n\n` |
| 最大チャンク長 | 1024（1000でもよい） |
| チャンクのオーバーラップ | **0**（チャンクごとに話題が完結しているため。重ねると隣の話題が混ざる） |
| 連続するスペース、改行、タブを置換する | **オフ**（チャンク内の改行を保つ） |
| すべてのURLとメールアドレスを削除する | オフ（出典のURLを残す） |

「チャンクをプレビュー」で、下の表の見出しで始まるチャンクに、その下の行が全部入っていることを確かめてから保存する。見出しだけ・1行だけのチャンクになっていたら、識別子か置換の設定が違う。

## 更新手順

モデルやデータを更新したら、町丁目の事実とRAGを作り直す。

```bash
UV="uv --system-certs run --with-requirements tools/requirements-surface-water-balance.txt python"
$UV tools/build_town_facts.py      # data/naisui_poc/02_processed/town_facts/ を更新
$UV tools/build_rag_markdown.py    # RAG/02_町丁目_*.md を更新
```

PyPIにつながらないときは、pyshedsを外してuvのキャッシュだけで動かせる（この2つのスクリプトはpyshedsを使わない）。

```bash
UV="uv --system-certs run --offline --with numpy --with rasterio --with geopandas --with scipy python"
```

`01_地域の背景.md` と `03_用語とデータの説明.md` は、出典を確認したうえで手で更新する。
