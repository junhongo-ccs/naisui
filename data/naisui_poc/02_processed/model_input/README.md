# 下水道台帳を1D/2D内水モデルへ取り込むための入力スキーマ

このフォルダは、中延・二葉PoCで下水道台帳をGIS・内水氾濫モデルに取り込む際の**空テンプレート**です。現時点では台帳由来の管渠データを含みません。東京都下水道台帳を正規の方法で確認した後に入力します。

段階1・初期段階2では、管網を作らず、`../surface_drainage_capacity.csv` の一律排水能力を用いる簡易2Dモデルを基準とする。管網テンプレートは、実績との差が大きい場所を重点的に精度向上する段階で利用する。

## 座標・標高の前提

- 平面座標: 管網データは JGD2011 / 平面直角座標系 IX（EPSG:6677）で整備することを推奨
- 標高: 台帳に記載されたT.P.基準とDEMの標高基準を統一する
- 現行の地表モデル（`tools/run_pysheds_surface_routing.py`）は、DEMタイルをWeb Mercator（EPSG:3857）のまま計算している（名目画素4.78m、地上約3.88m四方）。体積・面積は地上面積で計算する。管網と接続する段階で、DEMをEPSG:6677へ変換するかを判断する（`docs/01_概要・計画/PLATEAU導入計画.md` 2.2節）

## テーブルの役割

| ファイル | 要素 | GIS形状 | 役割 |
| --- | --- | --- | --- |
| `sewer_nodes.csv` | マンホール・ます・吐口 | Point | 1D管網のノード。地表セルと接続する地点。 |
| `sewer_links.csv` | 管渠 | LineString | ノード間を結ぶ1Dリンク。管内水理を計算する。 |
| `drainage_facilities.csv` | ポンプ場・貯留施設・水門等 | Point/Polygon | 排水・貯留の能力と運転条件を表す。 |
| `surface_node_links.csv` | 地表セルとノードの接続 | Table | 雨水流入と溢水を双方向にやり取りする接続条件。 |

## 作業手順

1. 下水道台帳からマンホール、管渠、吐口、ポンプ・貯留施設を抽出する。
2. `node_id` と `from_node_id` / `to_node_id` を設定し、管網の接続性を検証する。
3. 管底高、地盤高、管径、断面、勾配を確認し、標高基準を統一する。
4. DEMを地表解析用のセルへ変換し、各ノードに `surface_cell_id` を割り当てる。
5. `surface_node_links.csv` に流入・溢水のルールを設定する。
6. 過去の降雨・浸水実績で再現性を検証してから、シナリオ解析やリアルタイムデータ同化へ進む。

## モデル化の注意

- 台帳の不足値を推測で埋める場合は、`data_quality` と `source_note` に必ず記録する。
- 宅地内・私道下の排水設備は公開台帳に含まれないため、モデルの対象外または別途調査データとして管理する。
- マンホールの地表高より管内水位が高くなる場合に溢水を許容するなど、1D/2Dの交換条件は採用する水理エンジンに合わせて設定する。
- DifyやChatGPTは、計算結果・データ出所・前提条件を説明する役割とし、水理計算の代替にはしない。

## 一律排水能力を使う簡易2Dモデル

初期PoCでは、各地表セルの排水能力を一律 `50 mm/h` とする。降雨強度から排水能力と、別途設定した浸透能力を差し引いた余剰雨水を、DEMの勾配に沿って地表流として扱う。

```text
余剰雨水 = max(0, 降雨強度 - 排水能力 - 浸透能力)
```

これは下水道の実際の管径・管内水位・ポンプ運転を再現するものではない。結果は「一律の排水能力を仮定した地表湛水リスク」であり、個別の浸水深・溢水地点の予測値としては扱わない。過去実績、浸水想定、現地観測で比較し、必要な区域だけ1D管網モデルへ拡張する。
