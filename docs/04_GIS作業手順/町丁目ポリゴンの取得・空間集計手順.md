e-Stat（政府統計の総合窓口）からの**町丁目境界データの入手方法**と、すでに準備されている**空間集計スクリプト（`tools/export_risk_lookup.py`）の動作メカニズム**について、具体的に解説します。

---

### Step 1: e-Statからの町丁目境界データ取得手順

統計局の国勢調査小地域（町丁・字等）境界データを取得し、プロジェクトフォルダへ配置する手順です。

1. **e-Statの境界データダウンロードページへアクセス**
   * [e-Stat 地図で見る統計（統計GIS）データダウンロード](https://www.stat.go.jp/data/chiri/map/index.html) にアクセスします。
2. **対象データの絞り込み**
   * **統計データ名**: 令和2年（2020年）国勢調査 ＞ 小地域（町丁・字等）
   * **データ形式**: **Shapefile** または **GeoJSON**（世界測地系 / JGD2011）
   * **都道府県・市区町村**: 東京都 ＞ 品川区（13109）
3. **ファイルのダウンロードと配置**
   * ダウンロードしたZIPファイルを解凍します。
   * 解凍された境界ファイルを、`data/naisui_poc/01_raw/boundaries/` フォルダ配下に **`shinagawa_town_2020.geojson`**（またはShapefile一式）として配置します。
   * ※e-Statの標準属性名では、町丁目名が入るフィールドは **`S_NAME`**（例：「中延１丁目」「二葉２丁目」）となっています。

---

### Step 2: 空間集計スクリプト（`export_risk_lookup.py`）の仕組み

このスクリプトは、シミュレーション出力である**ラスタ（最大湛水深 GeoTIFF）**と、**ベクタ（町丁目ポリゴン GeoJSON）**を重ね合わせ（Zonal Statistics / ゾーン統計）、LLMが扱いやすいサマリー指標を自動抽出する役割を果たします。

```text
 [最大湛水深 GeoTIFF]  ＋  [町丁目ポリゴン (shinagawa_town_2020.geojson)]
         ↓
  ① 座標系（CRS）の自動照合・投影変換
  ② 対象町丁目（中延1〜6丁目・二葉1〜4丁目）のフィルタリング
  ③ ポリゴンごとのラスタセル値抽出 (ゾーン統計)
         ↓
 [risk_lookup_sc_{scenario}.json (Dify用ナレッジ)]
```

#### 内部で計算・抽出される指標の算出ロジック

* **空間重なり判定**: 
  GeoTIFF（Web Mercator解像度約4.78m）と GeoJSON（JGD2011）の座標系（CRS）のズレをGeoPandasで自動補正し、各町丁目ポリゴン内に含まれるメッシュ（セル）群を切り出します。
* **最大湛水深 (`max_depth_m`)**: 
  ポリゴン内に含まれるセルのうち、**最も高い水深値（ピーク水深）**。
* **平均湛水深 (`mean_depth_m`)**: 
  ポリゴン内全セルの平均水深（地域全体の平均的な被害度）。
* **0.2m以上浸水面積率 (`inundated_area_ratio_02m`)**: 
  歩行障害や床下浸水リスクが生じる**「0.2m以上」のセルの個数 ÷ 全セル数**で算出。特定の町丁目内で危険箇所が占める割合を示します。
* **ピーク時刻 (`peak_time_min`) & リスク区分 (`risk_level`)**: 
  最大湛水深に応じて「道路冠水レベル」「床下浸水注意レベル」などの定性的なリスク区分を割り振ります。

---

### Step 3: コマンド実行と出力の確認

境界ファイルを配置したら、以下のコマンドで集計を実行します。

```bash
uv --system-certs run --with-requirements tools\requirements-surface-water-balance.txt python tools\export_risk_lookup.py --scenario-dir data\naisui_poc\02_processed\surface_water_balance\sc_80mm_peak --towns data\naisui_poc\01_raw\boundaries\shinagawa_town_2020.geojson --name-field S_NAME
```

#### 生成される JSON 構造の確認ポイント (`risk_lookup_sc_80mm_peak.json`)
実行が成功すると、指定シナリオのフォルダ配下に以下のようなJSONが生成されます。

```json
{
  "scenario_id": "sc_80mm_peak",
  "towns": {
    "二葉2丁目": {
      "max_depth_m": 0.42,
      "mean_depth_m": 0.11,
      "inundated_area_ratio_02m": 0.28,
      "peak_time_min": 30,
      "risk_level": "床下浸水注意（一部で膝下程度の冠水可能性）"
    },
    "中延3丁目": {
      "max_depth_m": 0.14,
      "mean_depth_m": 0.03,
      "inundated_area_ratio_02m": 0.00,
      "peak_time_min": 20,
      "risk_level": "道路冠水注意（軽微）"
    }
  }
}
```

このJSONが完成すれば、**「段階3（Dify/LLM連携）」のナレッジ登録**に必要なデータ構造がすべて出揃います！
