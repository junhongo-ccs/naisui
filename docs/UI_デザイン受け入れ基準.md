# 内水氾濫AI/GIS PoC UI — デザイン受け入れ基準

## 対象

中延・二葉 内水氾濫AI/GIS PoCのチャット中心UI（PCは操作可能な地図を併設、モバイルはチャットのみ）。

## 必須要件

| 項目 | 受け入れ条件 |
|---|---|
| レイアウト | Tailwind CSSで実装し、情報密度は一般的なWebチャットより高く保つ。デスクトップは地図とチャットの2列グリッドとし、右端の状態・根拠ペインは設けない。チャット列は最小360px・最大520pxに制限し、大画面では地図列だけを拡張する。 |
| モバイル | スマートフォン幅でも、質問入力・送信・回答閲覧・根拠確認が横スクロールなしで操作できる。 |
| 主画面 | チャットを主導線とする。PC（1024px以上）では操作可能な内水氾濫ハザード地図（＋土のう置場マーカー）を併設する。モバイル（1023px以下）は地図を設けず、チャットのみで完結させ、地理情報は文章、地点名、数値、根拠カードで伝える。 |
| 町丁目の指定 | 既存データがある10町丁目（`中延一〜六丁目`、`二葉一〜四丁目`）からのボタン選択を基本とし、PC・モバイルとも自由入力を必須にしない。PCは地図クリックでも同様に選択できる（クリックは入力欄への反映のみで自動送信しない）。 |
| 地図データ | PCの地図はQGIS成果物（ベクタ/ラスタ）・土のう置場データ・避難所データ（品川区防災ポータルの公式一覧から中延・二葉分を特定しジオコーディング）をビルド時にWeb地図用形式（GeoJSON／着色PNGオーバーレイ）へ変換したものを表示し、都度変換しない。質問・再描画のたびに地図コンポーネントを白画面化・再描画しない。解析結果・地理情報はキャッシュし、同じシナリオは再利用する。地図の凡例には「校正前のスクリーニング結果」である旨を常時表示する。避難所のリアルタイム開設状況は未連携のため、当面「未確認」と表示する。 |
| 配色 | 背景は `#FAFAFA`。キーカラーは緑みの青（teal系）とし、同色相の明暗で状態・強調を表現する。警戒表現だけは十分なコントラストを確保する。 |
| 文字 | チャット本文は `15px` または `16px`。行間は可読性を優先し、本文で12〜14pxを使わない。 |
| 操作 | ローディング、送信不可、再試行、根拠不足を状態として明示する。回答中も既出の回答・入力欄を不必要に消さない。 |

## 推奨画面構成

```text
PC（1024px以上、1920×1080基準。大画面では地図列のみ可変）
┌────────────────────────────────────────────────────┐
│ ヘッダー: 対象地域 / 公式情報の確認導線                           │
├──────────────────────────────────┬─────────────────┤
│ ハザード地図（操作可能、可変幅）        │ チャット（360〜520px） │
│ ・ズーム / パン / 凡例                 │ ・町丁目ボタン選択      │
│ ・校正前ステータス常時表示               │ ・質問と回答            │
│ ・土のう置場・避難所マーカー             │ ・リスクの要約 / 安全上の注意 │
│ ・町丁目クリック→入力欄へ反映            │ ・出典 / 不確実性       │
│                                        │ ・質問入力 + 送信       │
└────────────────────────────────────────────────────┘

モバイル（360px〜1023px、地図なし）
┌──────────────────────────┐
│ ヘッダー: 対象地域              │
├──────────────────────────┤
│ 町丁目ボタン選択（10件）       │
├──────────────────────────┤
│ チャット（全面）              │
│ ・質問と回答                 │
│ ・リスクの要約 / 安全上の注意   │
│ ・近くの土のう置場（テキスト＋外部地図リンク）│
│ ・根拠・計算条件（折りたたみ）  │
├──────────────────────────┤
│ 質問入力 + 送信              │
└──────────────────────────┘
```

モバイルでは地図を持たず、地図関連コード自体を読み込まない。町丁目はボタン選択を基本とし、自由入力を必須にしない。近くの土のう置場・避難所はテキストカードで提示し、経路確認は外部地図アプリへのリンクに委ねる。避難所の開設状況はリアルタイム連携が未実装のため「未確認」と表示する。

## 非機能・安全要件

- LLMは公式の警報・避難情報より優先されない。
- 個別の避難先・行動を断定しない。回答は条件、根拠、公式情報の確認を併記する。
- `scenario_summary.json`、`risk_lookup_*.json`、土のう置場データ、避難所データ（位置は取得済み、稼働状況は未連携のため`unknown`）を回答根拠として保持する。
- 同じ `scenario_id` の計算・取得結果はキャッシュキーとして再利用する。

## 検収チェック

- [ ] 幅360px相当で送信・閲覧・根拠表示を完結できる。
- [ ] チャット本文が15px以上である。
- [ ] 背景 `#FAFAFA` とteal系キーカラーが適用されている。
- [ ] PC（1024px以上）でハザード地図が操作可能であり、モバイル（1023px以下）には地図が表示・読み込みされない。
- [ ] PC地図の凡例に「校正前のスクリーニング結果」である旨が常時表示されている。
- [ ] PC・モバイルとも既存10町丁目からのボタン選択で操作を完結でき、自由入力が必須になっていない。
- [ ] PC地図に土のう置場マーカーと避難所マーカーが表示され、避難所の開設状況は「未確認」と表示される。
- [ ] PCは地図とチャットの2列構成で、右端の状態・根拠ペインがない。チャット列は最小360px・最大520pxに収まる。
- [ ] PC地図列の幅が変わると、選択中の町丁目を現在の地図コンテナ寸法で再度`fitBounds`し、ノートPC・大画面・外部ディスプレイで中心位置がずれない。
- [ ] 同一シナリオで再質問しても地図／解析結果を初期化・白画面化しない。
- [ ] 回答に計算対象時刻・シナリオ・限界または公式情報確認の導線がある。

詳細な技術要件・状態一覧・検収チェックの全体は `docs/中延二葉_チャットUI_要件定義.md` を正とする。
