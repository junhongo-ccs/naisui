# 2026-09-24 城南地区CSV座標検証・引継ぎ

対象: 中延・二葉 内水氾濫AI/GIS PoC。次の担当者・Claudeが今日のQGIS作業を繰り返さずに再開するための記録。

## 1. まず結論

- 東京都の2018年版「城南地区河川流域浸水予想区域図」のCSV点群は、当初WGS84（EPSG:4326）として表示すると、既存のPDF派生ハザードより南東にほぼ一定量ずれて見えた。ユーザーがこのずれを発見した。
- CSVの座標値を**Tokyo Datum（EPSG:4301）として解釈**し、WGS84へ変換した点群では位置関係が大きく改善した。CSV2の全708,938点を変換した作業用GeoPackageを作成し、QGISで浸水深0.1m以上に絞ると、PDF派生レイヤと大まかな分布がよく似ていることをユーザーが目視確認した。
- これは座標解釈とPDF地理参照への**補助的な裏付け**である。CSVとPDFは異なる浸水想定図に対応するため、浸水範囲・深さの一致やモデル精度の向上を意味しない。**モデル本体、パラメータ、リスク指標、UIは今日は変更していない。**
- このPoCは社内・グループ内での紹介も未定の試作である。今日以上の細かな測地系精度追求やQGISの見栄え調整を優先しない。

## 4. 今日実施した検証

1. CSV1・CSV2をQGISに読み込み、品川区境界とPDF派生レイヤを重ねた。大量の点で描画が重くなったため、レイヤの表示切替とズームで確認した。
2. ユーザーが、WGS84仮定の点群がPDF由来の分布より**南東へきれいにずれる**ことを指摘した。この観察を無視せず、Tokyo Datum仮定を試した。
3. CSV2から同じ5,991点（浸水深0.1m以上）を抽出した二つのプレビューを作成した。WGS84仮定は `csv3_wgs84_assumption_preview.geojson`、Tokyo Datum仮定は `csv3_tokyo_datum_assumption_preview.geojson`。
4. Tokyo Datum仮定の点は概ね西へ290m、北へ360m移動した。PDF派生ポリゴン内に入る試料点はWGS84仮定の414/5,991点（6.9%）から、Tokyo Datum仮定の1,076/5,991点（18.0%）に増えた。これは**異なる図面間の補助的な比較**で、精度指標やIoUではない。
5. QGISでTokyo Datumの元CSVレイヤにEPSG:4301を設定しようとすると、優先変換には `tky2jgd.gsb` が必要でシステムに無かった。候補の `Ballpark geographic offset` は位置補正をしないため採用せず、ダイアログをキャンセルした。**保存済みQGISプロジェクトの元CSVレイヤはEPSG:4326のまま、表示OFFである。**
6. 利用可能な概算変換 `EPSG:15484`（公称精度9m）をGDALで使い、CSV2全708,938点をEPSG:4326のGeoPackageに変換した。プレビューと同じ変換結果になることを座標値で確認した。
7. QGISに全件GeoPackageを追加し、`"depth_m" >= 0.1` をフィルタとして設定。338,157点が条件に該当する。ユーザーはPDF派生レイヤとの位置・分布がよく似ていると目視確認した。プロジェクトを保存した。

QGISの `depth_m >= 0.1` は**プロジェクトに保存された表示フィルタ**。GeoPackage自体には全708,938点が入っている。QGISで改めてエクスポートする必要はない。後続の集計・比較では同じ条件をコード側でも指定する。

保存済みQGISプロジェクトの主要レイヤ状態をXMLで確認済み: 全件GeoPackage=表示ON、Tokyo Datumプレビュー=OFF、元CSV1/CSV2=OFF、PDF派生ハザード=ON、OSM=ON。PDF専用プロジェクトは別ファイルのまま。

## 6. 解釈の範囲

**確認できたこと**: WGS84仮定で見えた系統的な南東へのずれはTokyo Datum仮定で改善し、全件版でもCSV点群とPDF派生レイヤの大まかな分布は似ている。PDFの地理参照が数百m単位で大きく外れている可能性は低くなった。

**まだ確認していないこと**: CSV原典の測地系メタデータ、CSV1の全件変換、浸水深0の意味、両図面の範囲・深さの厳密な一致、モデルとの定量比較。CSVとPDFは別図面で、今日の重ね合わせだけでは一致率やモデルの予測精度を主張できない。

**変更していないこと**: 採用モデル、現在のシナリオ、`risk_lookup`、PDF派生ポリゴン、Dify/UIの実装。今日の作業はモデルの精度改善ではなく、補助データの位置確認と作業用形式への変換だった。

## 7. 次回の作業順と終了条件

1. **GISは必要最小限で区切る。** QGISを開き直す、色を整える、グリッドファイルを探し続ける作業は必須ではない。必要なら全件GeoPackageの `depth_m >= 0.1` を既存モデルの現行シナリオと概略比較し、合う場所・合わない場所を数件メモする。異なる浸水想定図であることを記す。ここでCSV検証を終了してよい。
2. **モデル精度の改善と区別する。** 必要な校正・検証はR7.9.11浸水実績を主とする既定方針に従う。CSV/PDFの重なりをモデル精度の改善として報告しない。
3. **PoC本体へ戻る。** [既存引継ぎ](../00_現状・引継ぎ/中延二葉_PoC_引継ぎ・タスクリスト.md)の直近優先事項はDify＋RAGのチャットUI検証。今回のCSVをUIへ直接追加することは、現時点の必須作業ではない。
