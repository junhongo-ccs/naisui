## 2. 照合結果：モデル順位 vs 実績順位（Spearman順位相関）

対象は 9町丁目（実績CSVに存在するもの）。2026-09-15に`sc_50mm_const`/`sc_80mm_peak`も`pysheds_surface_routing`で計算済みとなったため、3シナリオ全てで再照合した。

**同値（tie）について**: 照合対象9町丁目には、モデル側（特に`pysheds_sensitivity`の`max_depth_m`は凹地容量キャップ値ちょうどに張り付くため同値が多い、第3章参照）だけでなく、**正解データ側にも同値がある**（中延五丁目167棟＝二葉一丁目167棟）。単純な整数順位では同値を正しく扱えないため、以下は平均順位法（tied rank）でSpearman相関を算出した値である。第6章の再現スクリプトもこの方式に修正済み。

| sc_100mm_extreme | max_depth_m | −0.251 |
| sc_50mm_const | area_over_threshold_ratio | 算出不能（全町丁目0、同値） |

### 判明した4点

**(1) `max_depth_m` はリスク指標として不適切**

pysheds系で実績と**負相関**（sc_100mm_extremeで−0.25、sc_80mm_peakで−0.05、pysheds_sensitivityで−0.20）。単一セルの最大値であり、DEMアーティファクト（`depression_candidates` に最大9.14mの候補が存在）に支配される。`pysheds_sensitivity`は凹地容量キャップ値ちょうどに張り付く町丁目が多く（第3章）、`max_depth_m`の同値率が高い（例: cap1mで9町丁目中5町丁目が同値）ことも、この指標の信頼性の低さと表裏一体である。

この結論自体は相関係数の精度に依存しない。中延三丁目が最上位に出るが実績は8位/9という具体例が、指標として不適切であることを独立に示している。

現行の `export_risk_lookup.py` はこの指標でラベルを付けており、その結果 **中延三丁目が最上位**になっている。実績では **8位/9**（36棟）である。逆に実績1位の中延六丁目（218棟）は上位に出ていない。

**(2) `area_over_threshold_ratio` に切り替えると符号が反転する**

`pysheds_surface_routing`で sc_100mm_extreme はρ=+0.536、sc_80mm_peakはρ=+0.611。上位3町丁目は 二葉三丁目（実績4位）、中延六丁目（実績1位）、二葉一丁目（実績3位）で、実績と整合的な並びになる。

**(3) sc_80mm_peak が sc_100mm_extreme より実績をよく説明する**

ρ=+0.611（sc_80mm_peak）は+0.536（sc_100mm_extreme）を上回り、後述の有意水準の目安（n=9で概ね0.60以上）に達している唯一のシナリオである。

~~実績は31年間の累積であり、その大半は極端事象ではなく中規模豪雨由来と考えられるため、80mm相当のシナリオの方が実績をよく説明するのは解釈として整合的である。~~

**この解釈は誤りだった（2026-09-15訂正、下記2.1参照）。** 31年累計は実質的に平成11年8月29日の単一イベント（集中豪雨）が54.0%を占め、町丁目によっては97%に達する。「中規模豪雨由来」ではなく「1999年の1イベント」がほぼ全てである。sc_80mm_peakが優位な理由についての解釈としては成立しない。ただしρの数値自体（+0.611 > +0.536）は正しい。ただしn=9のままであり、「目安を超えた」以上の主張はしない。

### 2.1 重要な訂正: 正解データは実質「1999年の1イベント」（2026-09-15追記）

別セッション（naisui-f4）の指摘を原典PDF（`data/naisui_poc/01_raw/records/shinagawa_chome_inundation_history.pdf`）から独立に再計算し、確認した。

- 区内全域の31年累計5,097棟のうち、**平成11年8月29日（集中豪雨）単独で2,751棟＝54.0%**
- 町丁目別の同イベント寄与率（例）: 二葉四丁目97.4%、中延三丁目88.9%、二葉二丁目88.0%、二葉一丁目85.0%、二葉三丁目82.4%、中延五丁目76.0%、中延二丁目66.7%、中延六丁目61.9%
- 検証方法: PDFをテキスト抽出し、「区内全域」行の平成11年8月29日列（床下1,137棟＋床上1,614棟＝2,751棟）と、中延六丁目の同列（床下66棟＋床上69棟＝135棟／218棟＝61.9%）を独立に再計算。原典指摘と完全一致した。

**含意**:
- 本レビューが算出したSpearman ρ（+0.611、+0.536等）は「31年分の独立サンプル」に基づく検証ではなく、実質的に**1999年の1イベントに対する相関**である
- 1999年以降、都・区の下水道貯留施設整備が進んでいる可能性があり、現在の排水能力（50mm/h相当）を前提としたモデルを、整備前（1999年）の被害実績で検証していることになる。相関の正負・大小自体は今回の指標選定（`area_over_threshold_ratio`採用）の結論を覆すものではないが、「校正の正解データとして31年累計を使い続けてよいか」は再検討が必要
- 母数を増やす目的での「荏原地域への拡張」（第5章優先度B）は、荏原がこの1999年イベントでどう寄与しているか次第で効果が変わる可能性がある

### 2.2 R7.9.11データによる追加検証と正解データの方針確定（2026-09-15追記）

第2.1章のQRコードは区HPの同種の浸水実績一覧に戻るのみで、実数値の追加取得はできなかった（本セッションで確認）。令和7年9月11日浸水実績図（`shinagawa_disaster_map_2026-06.pdf`26ページ目）の6階級区分を、独立検証（本セッション、9/10町丁目でラベル確認。中延三丁目のみ未確定、詳細は第2.1章）に基づき`data/naisui_poc/02_processed/shinagawa_inundation_r7_0911_target.csv`として整理し、モデルとの順位相関を計算した（tied-rank Pearson、n=10）。

| シナリオ | 指標 | ρ（対R7.9.11） | 参考: ρ（対31年累計） |
| --- | --- | ---: | ---: |
| sc_80mm_peak | area_over_threshold_ratio | **+0.656** | +0.611 |
| sc_100mm_extreme | area_over_threshold_ratio | **+0.656** | +0.536 |
| sc_50mm_const | area_over_threshold_ratio | 算出不能（全町丁目0、同値） | 算出不能 |

31年累計との対比ではsc_80mm_peakのみが優位だったが、R7.9.11（最大時間雨量約120mm、現在のインフラ下）に対してはsc_80mm_peakとsc_100mm_extremeが**同率で最も高い**。100mm/hシナリオがR7.9.11の雨量条件に近いことと整合的である。n=10でも+0.656は有意水準の目安（片側5%相当、概ね0.55〜0.60前後）を上回る。

**正解データの方針（ユーザー承認、2026-09-15）**: 31年累計とR7.9.11の両方を保持し、**併用する**。
- R7.9.11: 現在のインフラ下・単一イベント・雨量条件が既知という点で、モデル校正の主たる参照とする
- 31年累計: 長期的な傾向の参考値として残す。ただし1999年イベントへの依存が強いことを常に明記する
- 中延三丁目のR7.9.11区分値（1-5件、`confidence: uncertain`）は今後実数値や高解像度データが得られ次第見直す

これにより、第5章優先度Aの「正解データの選定を再検討する」は決着とする。

簡易水収支v1（`surface_water_balance`）は `area_over_threshold_ratio` が**全シナリオ・全町丁目で0**であり、順位相関は算出不能（全町丁目間で差が無いため、rank()関数が辞書順でタイブレークし無意味な値を返す。第6章の再現スクリプトはこのケースを検出して明示的に弾くよう修正済み。旧稿にあった「−0.250」はこのtie処理バグによる誤りだった）。全シナリオで町丁目間の差がほぼ出ない（sc_80mm_peak では最大湛水深の町丁目間レンジが 0.00000m、全シナリオで閾値0.2m超の町丁目が 0/10）。

原因は構造的である:
- 排水能力が全域一律 50mm/h のため、局所的な排水不足を定義上表現できない
- `transfer_fraction_per_step=0.2`、`step_minutes=10`、全3ステップ。**水が横移動できるのは最大3セル＝15m**であり、集水が起きない

**「2系統のモデルのどちらを採用するか未決」という引継ぎ書の宿題は、これで決着とみなせる。**

### 2.3 建物棟数による実績の正規化（PLATEAU導入計画 フェーズ0B、2026-09-25追記）

実績は浸水**棟数**、モデル指標は**面積比**で単位が揃っていなかったため、PLATEAU建築物モデル（品川区2025年度版）から町丁目別の建物棟数を求め、実績を建物数で割った率でも順位相関を取り直した。モデルは変更していない。

**解釈**:

- 正規化しても順位相関はほとんど変わらない（R7.9.11で±0.02）。建物数は町丁目間で391〜774棟（約2倍）しか差がなく、実績の差（棟数で9〜218）に比べて小さいため。R7.9.11では正規化の主な効果は同順位の解消にとどまる
- 31年累計で順位が大きく動いたのは二葉一丁目（建物数最多の774棟。棟数2.5位→率5位）のみ。この町丁目はモデルで3〜4位のため、実績側の順位が下がると一致が悪くなる。80mm・100mmシナリオでρが下がった主な要因とみられる
- モデルと実績の順位が大きく食い違う町丁目（**二葉二丁目**: モデル9位・実績3〜4位、**中延三丁目**: 現行シナリオでモデル3位・実績7〜9位）は、正規化の前後で変わらない。不一致の原因は実績側の物差しではなく、モデル側にある
- n=9〜10のため、上記の差を改善・悪化とは判定しない（PLATEAU導入計画 2.1節）。今後のモデル改良の評価では、正規化前・後の両方を記録する

**制約**: PLATEAUの整備年度（2025年度）と実績の期間（1989〜2020年、2025年9月11日）は一致せず、建て替え・新築による建物数の変化は補正していない。31年累計は特にずれが大きい。

### 有意性についての但し書き

n=9でp<0.05（片側）に必要な臨界値は概ね0.60以上である。**sc_80mm_peak のρ=+0.611はこの目安を上回るが、sc_100mm_extreme のρ=+0.536は下回る。** どちらも「有望な方向」ではあるが、それ以上の統計的な主張（「検証済み」等）はしない。母数を増やす（荏原等へ拡張する、イベント単位に分解する）か、セル単位の空間一致で補強する必要がある。

## 4. 既存IoU評価との関係

`iou_pdf_derived_vs_pysheds_cases.csv` の結果は Case A〜C で **IoU 0.019（閾値0.1m）/ 0.011（0.2m）** と極めて低い。

ただしこれはモデルの失敗と即断できない。比較相手側に以下の差があるため:

- 公式図は **153mm/h・総雨量690mm**、モデルは 100mm/h シナリオ（条件が違う）
- 公式図側は **PDF派生ベクタ**（GCP RMSE 4.5m の地理参照を経た派生データ）
- モデル予測面積 293,066m² に対し公式図 2,852,544m²。**モデルは公式図の約10%の面積しか予測していない**

引継ぎ書の「Case Aを採用決定する根拠にはしない」という判断は妥当である。

**今後の校正の正解データとしては、PDF派生図ではなく浸水実績を主とすべきである。** 実績は一次データであり、派生を経ていない。（この「主」はモデル校正時の正解データ選択の話であり、後述5章のUI表示上の主従とは別の論点である）

## 6. 再現手順

リポジトリ直下から実行する。標準ライブラリのみで動く。

```bash
python - <<'PY'
import json,csv,glob,os
K={'1':'一','2':'二','3':'三','4':'四','5':'五','6':'六'}
rec={}
for r in csv.DictReader(open('data/naisui_poc/02_processed/shinagawa_inundation_history_target.csv',encoding='utf-8')):
    a=r['area']
    rec[a[:-3]+K[a[-3]]+'丁目']=int(r['underfloor_buildings'])+int(r['abovefloor_buildings'])

# 平均順位法（tied rank）。正解データ側にも同値がある（中延五丁目=二葉一丁目=167棟）ため、
# 単純な整数順位ではなくこちらを使う。
def avgrank(d):
    s=sorted(d,key=lambda k:-d[k]); out={}; i=0
    while i<len(s):
        j=i
        while j+1<len(s) and d[s[j+1]]==d[s[i]]: j+=1
        r=(i+j)/2+1
        for k in s[i:j+1]: out[k]=r
        i=j+1
    return out

def pearson(x,y):
    n=len(x); mx=sum(x)/n; my=sum(y)/n
    sx=sum((a-mx)**2 for a in x)**.5; sy=sum((b-my)**2 for b in y)**.5
    return sum((a-mx)*(b-my) for a,b in zip(x,y))/(sx*sy) if sx and sy else None

for p in ['data/naisui_poc/02_processed/pysheds_surface_routing/sc_50mm_const/risk_lookup_sc_50mm_const.json',
          'data/naisui_poc/02_processed/pysheds_surface_routing/sc_80mm_peak/risk_lookup_sc_80mm_peak.json',
          'data/naisui_poc/02_processed/pysheds_surface_routing/sc_100mm_extreme/risk_lookup_sc_100mm_extreme.json',
          'data/naisui_poc/02_processed/pysheds_sensitivity/median3_cap1m/sc_100mm_extreme/risk_lookup_sc_100mm_extreme.json',
          'data/naisui_poc/02_processed/surface_water_balance/sc_100mm_extreme/risk_lookup_sc_100mm_extreme.json']:
    t=json.load(open(p,encoding='utf-8'))['towns']
    common=[k for k in rec if k in t]; n=len(common)
    label=os.path.basename(os.path.dirname(os.path.dirname(p)))+'/'+os.path.basename(os.path.dirname(p))
    for metric in ['max_depth_m','area_over_threshold_ratio']:
        vals=[t[k][metric] for k in common]
        if len(set(vals))==1:
            # 全町丁目が同値（例: sc_50mm_constは排水能力と降雨が同水準で全て0）だと
            # sx=0 になり相関が定義できないため、算出不能として明示的に弾く。
            print('%-40s %-26s n=%d rho=算出不能(全町丁目同値=%s)'%(label,metric,n,vals[0]))
            continue
        rr,rm=avgrank({k:rec[k] for k in common}),avgrank({k:t[k][metric] for k in common})
        rho=pearson([rr[k] for k in common],[rm[k] for k in common])
        print('%-40s %-26s n=%d rho=%+.3f'%(label,metric,n,rho))
```
